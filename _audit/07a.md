## 无问题抽样

- **Q1 因果掩码**：`np.tril(ones(t,s), k=s-t)` 我按行展开验证：`t=3,s=5` 得到 `11100 / 11110 / 11111`，`t=1,s=5` 全可见；「偏移必须是 S−T、每行至少留一个可见 key」两条都成立，正是 KV cache 单步解码最容易写错的地方。
- **Q3 KV cache 显存账**：`2·32 层·32 头·128·2 B = 524288 B = 512 KiB/token`、`8192 × 512 KiB = 4 GiB`、GQA `h/kv=4 → 128 KiB` 三个数全部复算无误；掩码 `diagonal=s-t` 与 Q1 一致。
- **Q42 正则 DP**：按 `dp[i][j-2]`（零次）与 `dp[i-1][j]`（同列再来一次）实现后，和 `re.fullmatch` 在 `aa/a`、`aa/a*`、`aab/c*a*b`、`mississippi/mis*is*p*.`、`""/a*`、`aaa/a*a`、`""/""` 等 9 个用例上逐一相等；首行初始化与「`*` 只修饰前一元素」也对。
- **Q56 paged block manager**：实际跑过：`fork` 后 `ref` 由 1→2；向共享尾块追加触发且只触发一次 COW（`ref 2→1`，新块 ref=1），**满块从不 COW**（`filled=4,B=4` 时直接申请新块）；`free_seq` 两个序列释放后所有 `ref` 归零、块全回池。与我手推的「只有部分填充的尾块会是 COW 目标」一致。
- **Q58 NMS**：跑过 `scores=[0.9,0.8,0.7,0.6]`、默认 0.5 阈值得 `[0,2]`（IoU 0.68 与 0.9 的两个重叠框被抑制），0.9 阈值下 `[0,1,2,3]` 全保留；`np.clip(...,0,None)` 与 `maximum(union,1e-9)` 两个防零处理都对。
