### 13-DeepSeek 1 复算（写进答案的算式）

MLA 缓存 = 每层每 token `512`（latent）+ `64`（解耦 RoPE）= 576 个数；V3 61 层 ⇒ 61×576 = **35,136**/token。

- 同层数 128 头 MHA：61×2×128×128 = 1,998,848 ⇒ 1,998,848 / 35,136 ≈ **1/57**
- 同层数 8 组 GQA：61×2×8×128 = 124,928 ⇒ 124,928 / 35,136 ≈ **1/3.6**
- 稀疏算力：37B / 671B = **1/18.1**

原「1/5–1/10」既不等于上面对 MHA 的比值，也不等于对 GQA 的比值，故整条替换为「元素数 + 基准」。另：报告建议改引论文摘要「相对 DeepSeek 67B 降低 93.3%」，但 67B 配置为 95 层 / 64 头 / 8 个 kv head（DeepSeek LLM 论文 Table 2），按每 token 元素算 95×2×8×128 = 194,560，对比 V2 的 60×576 = 34,560 只有 ~5.6×（≈82%），无法由配置复现 93.3%，说明摘要那个数用的是另一套测量口径；因此**没有**把这个数字写进答案，改为在答案里点明「倍数取决于基准」，避免用不可复算的数字替换原错误数字。
